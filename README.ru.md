# Replace Constants для PL/SQL Developer

[English](README.md) | **Русский**

Плагин заменяет обращения к PL/SQL-константам их значениями в выделенном фрагменте кода. Если выделения нет, обрабатывается всё активное окно. Объявления констант считываются из всего текста активного окна, а также из спецификаций и тел упомянутых пакетов доступных схем через представление `ALL_SOURCE`. Поддерживаются частные и публичные синонимы через `ALL_SYNONYMS`, зависимости пакетов загружаются рекурсивно.

## Примеры

### Пакеты в другом окне

Пусть в схеме есть следующие пакеты:

```sql
create or replace package package_first is
  c_status constant varchar2(10) := 'ACTIVE';
  c_limit  constant number := 100;
  c_day    constant date := date '2026-01-01';
end;
/

create or replace package package_second is
  c_status        constant varchar2(10) := package_first.c_status;
  c_another_limit constant number := 20;
end;
/
```

Пакеты не обязаны быть открыты в активном редакторе. При наличии соединения плагин читает упомянутые пакеты из `ALL_SOURCE` и рекурсивно загружает их зависимости. Например, запросы:

```sql
select package_first.c_status from dual;
select package_second.c_status from dual;
```

будут преобразованы в:

```sql
select 'ACTIVE' from dual;
select 'ACTIVE' from dual;
```

Обращения с именем пакета поддерживаются как в SQL-запросах, так и в PL/SQL-блоках.

### Пакет в том же окне

Если пакет объявлен в том же окне, его имя можно не указывать ни в PL/SQL-блоках, ни в SQL-запросах. Например, для следующего пакета:

```sql
create or replace package body app_api as
  c_status constant varchar2(10) := 'ACTIVE';
  c_limit  constant number := 100;
  c_day    constant date := date '2026-01-01';

  function get_items return sys_refcursor is
  begin
    -- ...
  end;
end;
```

можно выделить в другом фрагменте этого же окна:

```sql
select *
  from app_items
 where status = c_status
   and created_at >= c_day
   and rownum <= c_limit
```

После запуска плагина получится:

```sql
select *
  from app_items
 where status = 'ACTIVE'
   and created_at >= date '2026-01-01'
   and rownum <= 100
```

## Возможности

- Имена констант без кавычек распознаются без учета регистра.
- Поддерживаются локальные константы и обращения вида `package.constant` и `schema.package.constant`.
- При наличии соединения плагин загружает спецификации и тела пакетов текущей и явно указанных схем из `ALL_SOURCE`. Частные и публичные синонимы разрешаются через `ALL_SYNONYMS`; у синонимов владельца учитывается приоритет частного синонима над публичным.
- Обращения с префиксом `package.constant` и `schema.package.constant` разрешаются только по спецификации пакета. Константы, объявленные только в теле пакета, доступны по имени без префикса.
- Пакеты, упомянутые в загруженных спецификациях и телах, загружаются рекурсивно. Неквалифицированные имена внутри пакета разрешаются относительно схемы его владельца; повторная загрузка и циклы исключаются, глубина ограничена 32 уровнями.
- Если в обрабатываемом коде нет обращений с именем пакета, спецификации всех пакетов текущей схемы загружаются одним запросом, чтобы имена констант без префикса работали и вне окна пакета.
- Строковые, числовые, датированные и другие SQL-совместимые значения подставляются без изменения исходного выражения.
- Составные выражения заключаются в скобки: `c_size constant number := 10 * 2` превращается в `(10 * 2)`.
- Константы в инициализаторах других констант разрешаются рекурсивно. Повторные имена считаются однозначными, если после разрешения их значения совпадают.
- Идентификаторы внутри строковых литералов и комментариев не изменяются.
- Объявления констант не изменяются, даже если обрабатывается весь документ.
- Bind-переменные `:name` и переменные подстановки `&name` не изменяются.
- Поддерживаются обычные строки, `n'...'`, альтернативный quoting-синтаксис `q'[...]'` и идентификаторы в двойных кавычках.
- Изменение можно отменить стандартной командой **Undo** (`Ctrl+Z`).

## Сборка

Требуются Windows, CMake 3.20 или новее и C++17-компилятор. Основной вариант — Visual Studio 2022 с компонентом **Desktop development with C++**.

### 64-разрядная DLL

Откройте **x64 Native Tools Command Prompt for VS 2022** в каталоге проекта:

```bat
cmake -S . -B build\x64 -A x64
cmake --build build\x64 --config Release
```

Готовый файл: `build\x64\Release\ReplaceConstants.dll`.

### 32-разрядная DLL

Откройте **x86 Native Tools Command Prompt for VS 2022**:

```bat
cmake -S . -B build\x86 -A Win32
cmake --build build\x86 --config Release
```

Готовый файл: `build\x86\Release\ReplaceConstants.dll`.

Для PL/SQL Developer 16 и новее нужна 64-разрядная DLL. Для более ранних версий разрядность DLL должна совпадать с разрядностью PL/SQL Developer; плагин другой разрядности IDE проигнорирует.

## Установка

1. Закройте PL/SQL Developer.
2. Скопируйте `ReplaceConstants.dll` подходящей разрядности в подкаталог `PlugIns` каталога установки PL/SQL Developer. Например:

   ```text
   C:\Program Files\PLSQL Developer 16\PlugIns\ReplaceConstants.dll
   ```

   Фактический путь может отличаться. Для установки в каталог `Program Files` могут потребоваться права администратора.
3. Запустите PL/SQL Developer.
4. Откройте **Tools → Configure Plug-Ins…** и убедитесь, что **Replace Constants** присутствует и включен.
5. В меню **Edit** должен появиться пункт **Replace PL/SQL constants**.

Отдельный Oracle Client не требуется: обращения к базе выполняются через SQL API текущего экземпляра PL/SQL Developer.

## Использование

1. Откройте PL/SQL-код в Program Window или другом редакторе PL/SQL Developer.
2. Выделите SQL-запрос или его часть, в которой нужно заменить константы. Чтобы обработать всё окно, снимите выделение.
3. Выберите **Edit → Replace PL/SQL constants**.
4. Проверьте результат и выполните запрос. В строке состояния отображается число замен.
5. При необходимости нажмите `Ctrl+Z`, чтобы вернуть исходный текст.

Если совпадений нет, текст не изменяется и отображается поясняющее сообщение.

## Ограничения

- Для загрузки пакетов других схем и разрешения синонимов текущему пользователю нужны соответствующие права на чтение `ALL_SOURCE` и `ALL_SYNONYMS` и доступ к объектам. Синонимы, указывающие через `DB_LINK` на удалённую базу, не разрешаются. Без соединения остаются доступны объявления из активного окна.
- Плагин не выполняет выражения и не вычисляет их в Oracle. Например, `to_date('2026-01-01', 'YYYY-MM-DD')` будет подставлено как `(to_date('2026-01-01', 'YYYY-MM-DD'))`.
- Инициализатор должен быть допустимым SQL-выражением в месте подстановки. Значения специфичных для PL/SQL типов, например `boolean`, могут не подходить для обычного SQL.
- Если одно имя объявлено с разными значениями в нескольких областях видимости, неоднозначное обращение пропускается. Для пакетных констант используйте `package.constant`. Перед выполнением проверяйте преобразованный SQL.
- В тексте заменяются лексические обращения к известным константам, а не результат полного разбора семантики запроса. Если столбец имеет то же имя, что и константа, проверьте такой фрагмент вручную.

## Структура проекта

- `src/plugin.cpp` — интерфейс DLL PL/SQL Developer, чтение `ALL_SOURCE` и замена выделения или всего окна через `EM_REPLACESEL`.
- `src/constant_replacer.cpp` — лексический разбор объявлений и подстановка значений.
- `src/constant_replacer.h` — независимый от Windows API интерфейс ядра.
- `src/replace_constants.def` — имена экспортируемых функций.

Описание интерфейса плагинов находится в каталоге `PlugInDoc` установки PL/SQL Developer. Список официальных и сторонних плагинов: <https://www.allroundautomations.com/products/pl-sql-developer/plug-ins/>.
